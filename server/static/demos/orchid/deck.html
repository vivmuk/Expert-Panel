03 Market context · 8 public sources, linked

What the public pages say about Orchid.

Research brief · AI-generated from public pages

Orchid[3], formerly Zero/Mail0, is publicly positioned as an approval-first personal assistant that runs inbox triage, calendar, meeting prep, travel, and follow-ups, living in Gmail, Google Calendar, and SMS with drafts staying drafts until approved[1]. The public FAQ says it quietly handles email, calendar, meeting prep, and travel[2], and the homepage frames it as an assistant reached through messages that connects to the user's stack[3]. The legacy Zero product is an open-source, AI-native email client with MCP tooling: MCP.md lists get-thread-by-ID, send, draft, label, and bulk actions (MCP.md), and the AI router PR adds a /do/:action endpoint for email actions via MCP (PR #1198). For the client problem, Orchid should hand a thread to an agent as a durable, resumable thread object rather than a one-shot prompt: pass thread ID plus message history and labels, keep the agent's draft in a draft state until human approval, and return control to the thread with a visible status so the conversation is never dropped. Required artifacts: a thread-handoff contract (thread ID, message history, labels, permissions, approval gate), an agent status/ownership field on the thread, a draft-and-approve flow, and a sync/return path. Public sources support thread retrieval by ID and draft/send actions (MCP.md) and thread synchronization via the UI (PR #1679), but do not document a formal handoff contract, so the contract shape is an assumption. No source says the company commissioned this work.

    07 Synthesis

    What the panel converged on, and what it can't see.

    Synthesis

    The experts converge on a contract-first approach: model the thread as a durable, versioned object with a stable ID, append-only log, and an explicit, visible ownership state machine guarded by compare-and-swap and idempotency keys, so that agent takeover is a reversible lease rather than a silent transfer. The debate sharpens this into a return-path-centric design where the agent works draft-only inside a frozen thread envelope, approval binds to a revision hash, and control returns to a named human on completion, timeout, or human edit. Because public Orchid pages (orchid.ai, formerly Zero/Mail0) document thread retrieval, draft/send, and UI sync but not a handoff contract, the team should ship a provenance-annotated spec with an explicit assumptions register rather than freeze a large schema on unverified capabilities.

    Key themes
    1. 01Thread handoff as a durable, versioned, idempotent state transition with a CAS-guarded ownership lease and TTL, not a background action
    2. 02Draft-only default with a single approval gate bound to a revision hash, and a mandatory, visible return path to a named human
    3. 03Thread-scoped, time-boxed, revocable capability grants that never inherit ambient mailbox scope
    4. 04Legibility and provenance: visible owner/status in the thread, plus a Documented-vs-Assumed layer tagging every field to a public source or an open question
    Blind spots
    1. !Public sources are marketing-shaped and thin on handoff mechanics, so the contract risks encoding assumptions (stable thread IDs, durable objects, approval model) as confirmed requirements
    2. !The backend state machine vocabulary (offered, agent-held) may leak into sender-facing UI and confuse users; a plain-language status layer is needed
    3. !Concurrent human edits mid-agent-run and stale-draft approval are under-specified; conflict resolution (human edit wins, rebase) must be a stated, logged rule
    4. !The rebrand trail (Zero to Mail0 to Orchid) fragments the public record, so evidence may be stale or mismatched to the current product

          • Handoff buttonHUMAN
            Human in thread initiates handoff. Ownership state is rendered in the thread header at all times; no background takeovers. The client hands over by thread ID, not by copy.
          • Capability grantHUMAN
            Client mints the thread-local grant (scopes: read_thread, draft_reply, apply_label, propose_archive) with an expiry. The eligibility scorer can never mint a grant.
          • Eligibility score + confirmGATE Human gate Handoff confirmer
            Eligibility scorer (AI agent) scores the thread for agent-fit and proposes handoff; the Handoff confirmer (human) confirms or overrides and signs first contact per account. No state change without confirmation.
          • Handoff ContractSYNC ENGINE
            Thread Handoff Contract: unassigned → offered → agent-held → awaiting-approval → returned | reclaimed | failed. Every state transition is CAS-guarded on a monotonically increasing state_version; a stale writer loses.
          • Lease managerSYNC ENGINE
            The lease is owned by the sync engine, not the agent. Lease expiry returns the thread to the human automatically. Agents that can extend their own lease indefinitely are an anti-pattern.
          • Frozen envelopeAI AGENT
            Packet assembler (AI agent) builds the handoff packet (summary, intent, open questions, constraints, tone, deadlines, do-not-say list) sealed inside the frozen envelope. No new participants, attachments or messages beyond the watermark without re-freezing and re-approval.
          • Agent runtimeAI AGENT
            Thread agent replies in-thread inside the envelope; preserves quoting and subject. May write draft revisions only. Escalates on low confidence, new intent, or envelope breach.
          • Draft revisionsAI AGENT
            Thread agent drafts revisions inside the envelope; emits started and draft-ready. Draft-only by default. The thread agent can never approve its own revision.
          • Approval revision hashGATE Human gate Approver
            Approver (human) approves a specific revision hash or rejects. send_draft verifies hash and grant. Nothing leaves draft state without a human approval bound to a specific revision hash.
          • Send via syncHYBRID
            Send via sync engine. Permission checker (hybrid) verifies send-as identity, recipient scope, approval level. Send is rejected unless the revision hash matches an approval record and the grant is unexpired.
          • Return-path eventsSYNC ENGINE
            lease-return-path emits return-path events keyed by (thread_id, lease_id). On completion, failure, or TTL expiry it emits returned and ownership flips to the human, even if the agent dies silently.
          • Audit logSYNC ENGINE Human gate Auditor / reclaimer
            Append-only, hash-chained audit log; every tool call and transition lands here before its effect is visible. Auditor / reclaimer (human) reviews the trail and has one-click reclaim.
          • Anti-pattern listSTATE
            Every production run writes exactly one delta, drafted by the eval miner and ratified by a human. A delta that recurs twice triggers a schema or skill revision, not just a prompt tweak.

          13 30 / 60 / 90 rollout and evals · Target = a target, not a result

          30/60/90: what ships when, and how it's tested.

          Days0–30

          Ship the Thread Handoff Contract v1 and CAS state machine behind a flag; internal threads only. Build the audit log and header ownership state. Offline evals green on CAS, expiry, and approval mismatch.

          Days31–60

          Enable lease-return-path and frozen-envelope-approval for a small internal cohort; draft-only, human approves every send. Start the QHX loop; ratify the first anti-pattern deltas. Target zero approval-gate violations.

          Days61–90

          Open handoff to external recipients on opted-in accounts with first-contact human sign-off; enable one-click reclaim and online eval sampling. Review contract at v1.x with deltas folded in. Targets by day 90 ≥ 99% drop-free handoffs, 100% approval integrity, p95 reclaim < 2 s — all targets, not results.

          Offline evals

          (fixtures replayed against the harness)

          • CAS race: two writers, one stale — stale write must fail. Pass 100% rejection of stale state_version.
          • Lease expiry mid-draft: returned emitted, ownership flipped, no orphan draft sent. Pass 100%.
          • Envelope breach: draft referencing post-watermark message rejected. Pass 100%.
          • Approval mismatch: send with wrong revision hash rejected. Pass 100%.
          • Reclaim during send: human wins, agent notified. Pass 100%.
          • Packet quality rubric (intent, constraints, do-not-say present). Pass target Target ≥ 90% of fixtures score full marks.
          Online evals

          (production traces, sampled)

          • Handoff completion without drop: thread returns to human with conversation intact. Target ≥ 99%.
          • Approval-gate integrity: zero sends without matching approval record. Target 100%.
          • Escalation precision on low confidence / new intent. Target ≥ 95% recall on labeled traces.
          • Time-to-reclaim under one click. Target p95 < 2 s.
          • Audit completeness: every transition has a pre-effect log entry. Target 100%.
